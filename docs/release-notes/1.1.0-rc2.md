# apt-cacher-ultra 1.1.0-rc2

**This is an opt-in release candidate for testing the upcoming 1.1 release.
The recommended stable release remains 1.0.5.** Download the candidate's
binary or `.deb` from the release assets; the stable apt repository continues
to serve stable releases only.

RC2 focuses on detecting and publishing upstream updates sooner, and making
the causes of a delayed update visible in logs. It includes the earlier 1.1
work on flat repositories, snapshot consistency, signature verification,
garbage collection, HTTPS/ACME, readiness and usage statistics.

## Changes since RC1

- **Shorter defaults:** background release checks run every minute instead of
  every 15 minutes; prepublication package warming has a 15-second budget
  instead of five minutes. Warming remains best effort, and packages left
  unwarmed are fetched when clients request them.
- **Checks take priority over maintenance:** release probes run beside repair
  and manual reconciliation. Unchanged releases allow maintenance to finish;
  changed releases cause it to yield. Reserved metadata-probe capacity keeps
  bulk downloads from starving these checks.
- **Faster adoption:** metadata and hot packages download concurrently,
  mirror-sync retries run together, and transient member failures use a
  shorter retry schedule. The upstream idle-read timeout is now enforced.
- **Earlier client visibility:** metadata requests can wait up to five seconds
  for revalidation. Busy suites no longer spend a full minute waiting for a
  pause before the publication barrier starts holding requests.
- **Useful INFO diagnostics:** requests identify the snapshot served, last
  upstream check and known pending changes. Background work records its owner,
  phase, elapsed time and outstanding waits, including when database writes
  block progress. Adoption logs separate detection from publication delays.
- **Better hot-package tracking and reuse:** schema 10 remembers requested
  package identities across versions and reclamation. Verified cached content
  is reused, and warming does not extend the package's client-use timestamp.
- **Repository compatibility:** recover misserved plain `Packages`/`Sources`
  indexes from a declared compressed sibling, verifying both representations
  against the release's sizes and hashes (Raspberry Pi repositories, #32).
- **Packaging:** optional firewalld service definitions are included. The
  prerelease asset names agree with `SHA256SUMS`.

In the manual six-suite, 48-package burst, this main revision made all updated
candidates visible in **2m08s–2m30s**, versus **13m02s on 1.0.5**. The setup
transition improved from 6m34s on the earlier main to 1m56s–1m58s. These are
synthetic runs on a busy shared host, not an availability guarantee; download
delays were removed before installation verification. See the
[measurements and limitations](https://github.com/linsomniac/apt-cacher-ultra/blob/1.1.0-rc2/e2e/freshness-lab/README.md#comparison-after-merging-the-barrier-fix-2026-11-15).

## Before upgrading

Read the [full upgrade notes](https://github.com/linsomniac/apt-cacher-ultra/blob/1.1.0-rc2/docs/release-notes/1.1.0.md#before-you-upgrade).
In particular:

- Stop the daemon and back up the cache, any separate database directory
  (including its WAL), and configuration before testing. A disposable copy of
  an existing cache is preferable for the first upgrade.
- **RC2 migrates to schema 10. RC1 uses schema 9; 1.0.x uses schema 6.**
  Neither older binary can open the migrated database. Returning to RC1 or
  1.0.x requires restoring the pre-upgrade backup; reinstalling the older
  binary alone is insufficient. Auditing, garbage collection and suite
  reaping can remove cached content after the upgrade.
- Installing the `.deb` restarts a running daemon. Startup auditing and
  background cleanup can take time on a large cache.
- Offline/archive caches should set `gc.suite_idle_ttl = "0s"` before
  upgrading if idle suites must be retained. The suite reaper runs even with
  `gc.enabled = false`.
- Snapshot adoption remains opt-in. Load repository signing keys before
  enabling it. Restarting with adoption disabled forgets previously adopted
  suites so their metadata can refresh through the ordinary cache.

**Existing explicit configuration values are retained.** To receive the shorter
delays, edit these settings in the existing sections of your configuration:

```toml
[freshness]
periodic_refresh = "1m"
revalidate_wait = "5s"

[adoption]
hot_prefetch_budget = "15s"
```

Operators who prefer more prepublication warming can explicitly retain a
larger budget. This remains best effort; a current package list does not mean
every package is already cached for offline use.

## Downloads and installation

Assets include a standalone Linux amd64 binary, a Linux amd64 `.deb`, a source
archive, and `SHA256SUMS`. After reading the upgrade notes and backing up,
download `apt-cacher-ultra_1.1.0-rc2_amd64.deb` and `SHA256SUMS` into the same
directory:

```sh
sha256sum --check --ignore-missing SHA256SUMS
sudo apt install ./apt-cacher-ultra_1.1.0-rc2_amd64.deb
apt-cacher-ultra -version
sudo systemctl start apt-cacher-ultra
sudo systemctl status apt-cacher-ultra
```

Install only if the checksum check passes. The package's internal Debian
version is `1.1.0~rc2`, which sorts after RC1 and before stable 1.1.0. The
download filename uses `-rc2` because GitHub rewrites `~` in asset names.

## Remaining limits and feedback

- Metadata fetching, queueing, database commits and the publication barrier
  can still add latency. One benchmark run reached the barrier's 20-second
  hold limit during a slow commit; APT completed successfully, and the event
  did not recur in the repeat. Monitor `adoption_flip_barrier` outcomes and
  `acu_flip_hold_expired_total`; see the measurements linked above.
- Please report GC behavior on busy real caches ([#14](https://github.com/linsomniac/apt-cacher-ultra/issues/14)).
- `do-release-upgrade` needs the client's system certificate store to trust
  the proxy's MITM CA, or the proxy must be bypassed for that operation
  ([#19](https://github.com/linsomniac/apt-cacher-ultra/issues/19)). Disabling
  MITM does not provide a CONNECT pass-through tunnel.
- Signature compatibility exceptions and deferred integrity cases remain in
  [open decisions](https://github.com/linsomniac/apt-cacher-ultra/blob/1.1.0-rc2/docs/open-decisions.md#open).

Please report the version, relevant configuration with secrets removed, logs
and reproduction steps in [GitHub issues](https://github.com/linsomniac/apt-cacher-ultra/issues).
See the [full 1.1 release notes](https://github.com/linsomniac/apt-cacher-ultra/blob/1.1.0-rc2/docs/release-notes/1.1.0.md)
for the complete feature and upgrade details.
