# apt-cacher-ultra 1.1.0-rc1

**This is an opt-in release candidate for users willing to test the upcoming
1.1 release and report problems. The recommended stable release remains
1.0.4.** The stable apt repository is unchanged; download this candidate's
binary or `.deb` directly from the release assets to opt in.

1.1.0 includes substantial work across flat repository support, snapshot
consistency and scheduling, signature verification, garbage collection,
HTTPS/ACME, readiness checks, usage statistics, and separate database storage.

We would particularly welcome reports from existing 1.0.x installations,
users of flat or third-party repositories, and busy caches that have had
garbage collection problems. Please report your version, relevant
configuration (with secrets removed), logs, and reproduction steps in
[GitHub issues](https://github.com/linsomniac/apt-cacher-ultra/issues).

## Before testing

Read the [full upgrade notes](https://github.com/linsomniac/apt-cacher-ultra/blob/1.1.0-rc1/docs/release-notes/1.1.0.md#before-you-upgrade)
before installing. In particular:

- Stop the daemon and back up its cache directory, any separate database
  directory (including the WAL), and configuration before testing. Prefer
  a disposable copy of an existing cache for the first upgrade.
- The database migrates to schema 9, which 1.0.x cannot read. Auditing and
  cleanup can delete cached content. Returning to 1.0.x requires restoring
  the pre-upgrade backup; reinstalling the old binary alone is insufficient.
- Installing the `.deb` restarts a running daemon. Initial auditing and
  subsequent garbage collection can take time on a large cache.
- Offline/archive caches should set `gc.suite_idle_ttl = "0s"` before
  upgrading; the new idle-suite reaper operates even with `gc.enabled = false`.
- Snapshot adoption remains opt-in. Load repository signing keys before
  enabling it. Restarting with adoption disabled now forgets previously
  adopted suites so their metadata can refresh through the ordinary cache.

## Downloads and installation

The release assets include a Linux amd64 `.deb`, a standalone Linux amd64
binary, a source archive, and `SHA256SUMS`.

After backing up and reading the upgrade notes, download
`apt-cacher-ultra_1.1.0~rc1_amd64.deb` and `SHA256SUMS` from this release into
the same directory, then run:

```sh
sha256sum --check --ignore-missing SHA256SUMS
sudo apt install ./apt-cacher-ultra_1.1.0~rc1_amd64.deb
apt-cacher-ultra -version
sudo systemctl start apt-cacher-ultra
sudo systemctl status apt-cacher-ultra
```

Proceed with installation only if the checksum check passes. The Debian
package version is `1.1.0~rc1`, so the eventual stable `1.1.0` sorts newer.
No apt source changes are needed to install this downloaded package.

## Known limitations and feedback

- [Issue #14](https://github.com/linsomniac/apt-cacher-ultra/issues/14): this
  candidate includes the GC fixes; reports of cleanup behavior on real
  caches will help validate them before the stable release.
- [Issue #19](https://github.com/linsomniac/apt-cacher-ultra/issues/19):
  `do-release-upgrade` needs the client's system certificate store to trust
  the proxy's MITM CA, or the proxy must be bypassed for that operation.
  Disabling MITM does not provide a CONNECT pass-through tunnel.
- Signature compatibility exceptions, resource limits, and deferred
  integrity edge cases remain documented in
  [open decisions](https://github.com/linsomniac/apt-cacher-ultra/blob/1.1.0-rc1/docs/open-decisions.md#open).

See the [full 1.1 release notes](https://github.com/linsomniac/apt-cacher-ultra/blob/1.1.0-rc1/docs/release-notes/1.1.0.md)
for feature details, configuration changes, and upgrade behavior.
