## Robustness outside phase F (H)

- **F-21** GC's goroutines recover no panics (`gc.Run`, the pool-scan producer); sub-job C now runs there. Pre-existing. (H) (final review tests, declined to judge)
- **F-22** The junk scan's pool reads have no per-read timeout, so a hung filesystem stalls the reaper's run and its shutdown. Every pool reader shares this. (H) (final review concurrency, declined to judge)
- **F-23** `TestProfilingRoutesOptInAndPrivate` (`internal/admin`) fails rarely under load with `TempDir RemoveAll cleanup: … directory not empty` (subtest `disabled`). Reproduced at phase F's base 1667739 (1 in 60 loaded runs), never at its head in 60; phase F did not make it more likely. (Pre-existing; fix-round-1 observation, confirmed by the final review's tests lens)
- **F-24** GC sub-job B (`RunSnapshotGCBatch`'s displaced class, `internal/cache/gc.go:273-287`) does not exclude snapshots queued in `legacy_trust_audit`. With `gc.keep_displaced = 0` (allowed) it deletes a displaced, adopted, audit-deferred signed snapshot while the suite row stays, and no marker replaces it; when that snapshot was the base's only signed history, never-downgrade then admits an unsigned candidate (probe: phase F final re-review, cache group, `SP/rr-final/cache/zz_rr_probe_test.go`). The same class as spec C1, which ruling PF-12 closed for suite-row deletes only; pre-existing, and not reached with the default `keep_displaced` (a newer signed adoption marks the base; a newer unsigned one is refused while the deferred snapshot counts). Fix shape: run PF-12's `signedHistorySnapshotSQL` upsert before B deletes such a snapshot, or leave audit-queued snapshots out of B. (H; security-adjacent: take it early in the sweep) (final re-review, out of scope)
- **F-25** `HoldSuite`'s `release(true)` runs `FlipGate().Purge` inside its `once.Do` before `unlockDropped` (`internal/freshness/suite_lock.go:110-117`): a panicking Purge would leak the suite's mutex for every deleter, and `Forget`'s panic branch would raise that panic instead of its own. Speculative (Purge has no known panic) and pre-existing; a deferred unlock closes it. (H) (final re-review, logging, out of scope 3)
- **F-26** `sortCandidates`' AIDEV-NOTE (`internal/freshness/reaper.go`, PF-4 and PF-14) calls a regardless reap cheap because it has "no snapshot": true for junk (no current snapshot by definition), not for a legacy non-canonical row, which can carry one; its reap retires that snapshot and sub-job C deletes its package rows later, so 250 such reaps a run grow C's backlog (chunked; not the reaper's own cost).
